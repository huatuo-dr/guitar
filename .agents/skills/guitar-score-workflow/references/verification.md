# 校核与构建

命令从仓库根目录运行。选择与改动相关的检查；普通文字或 CSS 微调不需要复制整套数据测试。

## 构建入口

- 《偏爱》：`node scripts/build.mjs`。
- 现有其他单曲：`npm run build:houlai` 等，以 `package.json` 的实际脚本为准。
- 修改共享绘谱、页面或简易谱代码：`npm run build`，检查所有受影响的成品差异。
- 新曲的薄入口沿用 `scripts/build-houlai.mjs` / `scripts/build-canon.mjs` 的形式；同步加入总构建、清单及适用测试入口。

## 三层证据

1. **原图核对**：逐小节核对弦品、同响音、时值、换和弦拍点、歌词、技法和反复。重点重看装饰音、两拍小节、跨行弧线、房子、相似小节差异与末尾。程序通过不能证明最初的转录正确。
2. **数据与转换**：运行相关 `node --test tests/<name>.test.mjs`；音乐数据或共享语义变化可用 `npm test`。检查小节数、各声部时值、技法目标、实际演奏路线和歌词遍次。《偏爱》还要核对 AlphaTex 解析回读、弦索引及书写时值。
3. **浏览器与视觉**：运行现有相关浏览器脚本并查看截图。至少覆盖本次改动涉及的桌面/手机排版、两种行数或模式、打印与离线行为；新曲需建立自己的预期值与浏览器覆盖，不能仅运行硬编码旧曲目的套件。

简易谱共享改动用 `npm run test:simple-score`。首页清单变更用 `npm run test:home`。广泛影响全部页面的交互改动才扩大到 `npm run test:browser`。检查范围取决于影响面，已通过后无新问题不必反复重跑。

## 容易漏检的位置

- 手机可选 320px、390px 和横屏，桌面约 1280px；检查歌词/和弦碰撞和页面级横向溢出。用户选择放大时，谱面容器内部横向滚动是预期行为。
- 反复展开后每次小节实例 ID 唯一，导航能到达；刷新到重复小节后切回完整谱能映射到原小节。
- 比较简易谱展开后的和弦/歌词与原始路线预期。前奏、间奏和过门的完整保留按逐事件或 SVG 对照验证。
- 模拟打印检查完后用 `page.emulateMedia({media: null})` 清除覆盖，再生成 PDF；设成 `screen` 会使后续 PDF 错用屏幕样式。
- 查看 PDF 纸张方向及跨页边界，不只检查文件存在。`pdfinfo`、`pdftoppm` 可生成逐页预览；不要沿用历史文档中的固定页数。
- 下载的 HTML 用新的浏览器上下文、离线重开，验证两种视图及所需脚本/字体。首页另验 GitHub Pages 子路径和直接打开本地文件。
- 可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指向当前环境已有浏览器；依赖安装在项目内。

截图、PDF 和下载测试副本放 `artifacts/`，参考材料放 `tmp/`；两者均忽略。不要新增 `docs/superpowers/` 为版本管理内容。最后检查 `git diff --check` 与变更范围，成品应与源文件一起交付。
